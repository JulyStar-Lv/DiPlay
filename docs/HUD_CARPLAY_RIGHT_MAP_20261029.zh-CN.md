# CarPlay HUD 右侧地图接入

日期：2026-10-29。适用当前 J90K 普通 HUD 布局；正式包名为 `com.thunder.carplay`。

## 实现范围

新增独立的 `display-android` Android 画面契约，不改变 `display-api` 的结构化状态模型：

```text
CarPlay 辅助地图 → AndroidMediaSink → MapSurfaceConsumer
                                      ↓
                 vehicle-mzd / MzdHudMapOutput
                                      ↓
        原厂 MeterDisplay#0 → Framecast → Linux HUD

CarPlay 导航状态 → 原有 MzdVehicleDisplayFactory → 原厂导航 Binder
                                      ↓
                  同一工厂协调右侧窗口的显示条件
```

- CarPlay 侧负责把通用地图请求转换为 `maps:/car/instrumentcluster/map`、辅助流类型 111。
- `vehicle-mzd` 动态寻找唯一的 `MeterDisplay#0`，验证 800×480、有效、非主屏、未旋转且未关闭。不创建、改尺寸或替换原厂虚拟屏。
- 透明全屏 Presentation 只在 `[584,179,762,357)` 输出，区域为 178×178。
- 首版申请 352×352、15fps 辅助画面，四边安全区 28 源像素。此参数为接入起点；真实手机是否接受以及车标位置仍以实图验收。
- 根据解码器报告的实际可见宽高进行等比完整显示；意外宽屏来源留边，不拉伸、不直接裁掉路线。
- 等待有效导航数据、原厂导航焦点、导航模式切换完成和辅助流建立后创建窗口。
- 首个 TextureView 更新后显露视频；该事件是 Android 纹理观察，不能替代 HUD 图片确认。
- 导航结束、超时、失焦、断流、会话关闭或显示屏消失时移除窗口。重新建流创建新纹理，防止展示旧路线帧。
- SurfaceTexture 销毁后由解码器异步确认解绑，再释放 Surface / SurfaceTexture；解绑未确认时保留对象并记录错误。
- 地图窗口属于会话媒体 sink，Activity 重建不会单独终止地图输出。旧 lease 的迟到关闭不清除新 lease。

本阶段仅接地图视频与原有左侧 TBT；路名/ETA 的右侧叠加后续增加。没有辅助视频时继续现有 TBT，不生成虚构道路几何。

## 构建开关

普通源代码构建保持关闭。台架正式版明确传入：

```text
-PmzdHudEnabled=true -PmzdHudMapEnabled=true
-PmzdHudMediaSourceType=20 -PmzdHudAutomaticA2dpHandover=true
```

该开关在下次应用构建/安装及 CarPlay 新会话中生效；未新增设置页面控制。认证和签名使用本地私有环境。

## 真实手机验收顺序

1. 重新建立 CarPlay，会话日志应申请 352×352 / 15fps，并出现辅助流建立记录；不能仅凭请求成功判定手机有图。
2. 启动一条附近真实路线，保留 2 分钟。检查 `gate → window → format → first_texture_frame` 与同一时刻 HUD 原图，确认道路和车标与手机路线一致、无拉伸、无越界，左侧 TBT 正常。
3. 结束导航后保持 15 秒，右侧旧地图和左侧引导均应清除；再次启动同一路线，不能显示上次纹理。
4. 地图显示中断开 CarPlay、重新连接，检查旧画面清理和新会话恢复。原厂导航取得焦点时应让出右侧输出。
5. Apple 地图和高德分别记录。辅助流未建立、只有黑帧或收到 TBT 但无地图时，记录具体停止阶段，不计地图通过。

## 原生视觉对照与第二版参数

用户提供的原生参考图为800×480，右侧同为178×178。原生在53m路口前显示粗黄色路线、近距离路口和简化底图；首版CarPlay的323m样本为大范围深色地图，路名和路线偏小，车标靠右。两张图并非同一路线、同一距路口状态，不能把全部差异归因于接收端。

第二版仅修改 `vehicle-mzd` 的源画面请求：

| 参数 | 首版 | 第二版 |
| --- | --- | --- |
| 协商画面 | 352×352 | 256×256，编码对齐 |
| 输出区域 | 178×178 | 178×178 |
| 缩放比例 | 0.506 | 0.695 |
| 安全区域（源坐标） | [28,28,324,324) | [64,128,192,232) |
| 安全区域中心 | (50%,50%) | (50%,70.3%) |

较低的源画面尺寸用于减少HUD缩小渲染元素；安全区向下移动，向手机请求车标居中偏下并保留前方道路。安全区域不能保证高德遵循，实际车标、地图范围、字重仍需真实手机截图确认。保持完整画面等比显示，不以裁切或拉伸移动真实车标。

原生底图、路线配色、自动路口缩放和顶部蓝色引导图形并不由该尺寸参数控制。不能声称修改分辨率后即可复刻原生风格，也不能从左侧TBT推算不存在的道路几何。原生同等质量的结论继续保留待验。

### 256×256安装与实图结论

256版本已覆盖安装到台架，只保留 `com.thunder.carplay`；所需本地认证素材齐全，未安装测试包。CarPlay自动重连，高德新路线收到375m / 剩余2.7km / 6分，实际解码报告256×256。

- 120秒采集共22张800×480原图，全部散列正确；右侧区域的可见边界均为 `[584,179,762,357)`。
- 相比首版375m / 2.7km样本，路名更大，车标远离右边缘；仍有路名、目的地标识与车标挤在一起，手机并未保证车标恰好位于安全区中心。两次路线的道路构图、ETA也有变化，不能作为严格同帧A/B。
- 右侧地图传输、区域和本轮采样出图通过；**仍未达到原生简化路口图的视觉质量**。当前尺寸和安全区参数不能去除高德自行绘制的水印、摄像头、目的地等内容。结构化 `NavigationState` 只有动作、道路文字和距离/时间，未携带完整道路几何，无法据此重建真实路口。
- 另发现左侧里程/时间在39.8秒、102.4秒的2张采样中被原厂“--km”占位替代，后续采样均恢复；其他20张为2.7km / 6分。对应源数据和Binder周期发送未中断，没有导航模式关闭或失焦日志。此现象原因未确定，不把整页稳定性计为通过，也不未经验证将其归因于地图分辨率。
- 静止375m场景仍不能代替53m转弯前同场景测试；尚未验证行驶跟随、实际临近路口的缩放、重算和到达。
