## 4. 所有权及清屏补测

首次在真实 CarPlay 会话仍活跃时请求 SIM，页面拒绝启动，显示 `IllegalStateException`。第二次回放中，CarPlay 自动连接，在约 10.4 秒出现真实会话 start，SIM 输出被收回，随后截图中右侧区域为黑色。

第二次临时验证包没有完整暴露真实手机辅助视频输出，因此接管后的黑屏只用于确认 SIM 停止，不能作为手机地图恢复验收。随后通过 DiPlay 正常“断开连接”操作断开会话，第三次才完成整轮 8 案例回放。恢复正式版后另外验证了真实视频出图。

## 5. 恢复正式版后的真实 iPhone

用户重新连接后，保存 300 秒窗口的 **25 对主屏/HUD 截图**，并补采当前 1 对。主屏可见高德 CarPlay 正在导航。

另读取正式进程的有界诊断，确认启动事件发生在 300 秒采集开始之前。因此采集报告内 `mapEvents={}` 仅表示该窗口没有新地图生命周期事件，不能解释为没有辅助视频。

实际可追踪的链路：

```text
CarPlay session start
  → 辅助视频 stream active=true
  → 导航门控 allowed=true
  → display=1 / 800×480 / viewport=584,179,178,178
  → format=256×256 / contain
  → first_texture_frame
  → Linux HUD 实图
```

协商请求为 256×256 / 15fps，未测量手机实际视频帧率。

## 7. 下一步接入条件

硬件像素通路已验证。要使当前真实 CarPlay 也出现原厂风格道路图，需要进一步取得与手机选中路线一致的局部路线几何；要显示独立放大图，需要取得真实图片或带图的辅助视频，以及可确认的显隐状态。

当前的 `instruction_card` 辅助视频只有手机已合成的卡片像素，不能从中恢复道路几何，也不能仅凭 TBT、车道角度或 `sendNavigateCrossRoad(0/1)` 生成真实路口。下一轮应围绕真实数据来源验证，随后接入已通过台架的绘制及图层接口。
