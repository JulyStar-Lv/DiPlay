## 1. 结论

**已安装启用 HUD 的 DiPlay 台架包，并完成两层、每层 21 组的全部执行和截图审阅。42 组中，34 组显示符合预期、6 组部分符合、2 组音乐文字未显示。当前版本仍有显示问题，不能判定全部通过。**

两层分别验证：

1. `snapshot`：合成通用快照 → `vehicle-mzd` → 原厂 Binder → Linux HUD 画面。
2. `replay`：合成 iAP2 消息 → 生产 CarPlay 数据适配层 → 通用快照 → 同一车型驱动 → 原厂 Binder → Linux HUD 画面。

普通应用 UID `10117` 可以发现服务、获得焦点，并发送导航、音乐、电话内容。成功执行的 42 组共 90 次步骤快照核对全部匹配；这证明本批合成输入的数据链路一致。显示结论另按截图判定，未使用 Binder 返回值替代出图验收。

本批使用 J90K 台架、Android 14 / SDK 34；模块按项目要求命名为 `vehicle-mzd`，驱动针对已核验的 J90K 固件配置，不代表其他车型具有相同 ABI。

### 音乐显示路径的准确含义

本次音乐通过车型兼容模式 `sourceType=27`，将“歌名 / 歌手”写入已核验的 `lyricObj.curLyric` 单行显示通道。截图看到的是元数据组成的滚动文字，并非原生 CarPlay 来源图标、固定两行排版，也不证明 DiPlay 已获取真实歌词。本期未发送真实歌词或封面。

## 4. 待修问题及定位边界

### 4.1 相同导航内容重新进入后，动作图标和距离丢失

N08 补齐距离后显示左转 150m；紧接着 N09、N10 再次进入相同引导时，两层均只显示“现在”，剩余 5km / 2 分钟仍在。C01 也出现同样现象。通用快照中仍是左转、150m，导航内容事务也有返回记录。

这将问题范围缩小到快照之后的车型驱动、原厂异步模式切换/缓存及下游显示链路，尚不能指定唯一根因。现有驱动已经每秒刷新导航数值，因此单纯“再发一次”不能据本批结果认定有效。后续应对相同值/不同值重入、模式切换前后顺序及服务内部去重作差分取证。

### 4.2 长文本/emoji 组合未显示

M03 使用 `测试😀` 重复 40 次，驱动进行 UTF-8 字节边界截断；两层快照匹配、事务返回，但音乐行始终未出现。普通中文和英文可以显示。

本批未拆开测试“短 emoji”“长纯中文”和不同字节长度，因此不能直接归因为 emoji、长度上限或编码中的某一项。下一步需用上述对照确定可显示的字符及长度边界。

### 4.3 电话结束后，原音乐行未在采样时恢复

C01 的第 6 秒结束电话，第 7 秒截图中电话已消失，原歌曲行未恢复；两层一致。该用例在第 10 秒清理，结束电话后的有效截图只有第 7 秒，未验收更晚时刻是否自动恢复。

驱动当前对未变化的音乐 JSON 去重。需验证原厂电话覆盖后是否要求重发当前音乐，并补充更晚采样；该解释目前是定位方向，不能写成已经证实的根因或修复结果。
